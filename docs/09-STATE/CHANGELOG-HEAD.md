### Fixed — what we faced
- CI disk exhaustion (CI-FAIL-021/023): the coverage job holds two full
  builds and filled the runner disk. A free-disk step alone did not cure
  it; deleting `target/debug` between Test and Coverage broke the smoke
  test (it spawns `target/debug/detag-api` directly). Fix: move the
  binary aside before the delete and restore it after — green since CI #56.
- Schema-docs drift (CI-FAIL-022/025): the docs test hardcoded the table
  count; each new migration broke it (22→23→24). Fixed twice by bumping
  the count; the trap is recorded so the next migration bumps it too.
- Flaky config tests (FLAKY-007): three tests shared one fixed temp
  path; under nextest each test is its own process, so a sibling's
  cleanup deleted the file first. Fixed with per-test unique temp dirs.
- Flaky dunning tests (FLAKY-008): dunning tests share one test DB and
  the in-process mutex cannot serialize across nextest processes, so a
  sibling's row got counted. Fixed by serializing the dunning tests
  under nextest (max-threads = 1). Traps: `test-threads` is not a valid
  nextest key, and the filter must be `binary(dunning)`.
- Readyz flake (FLAKY-009): CI #64 failed on one test — /readyz
  answered 503 (db probe timed out, storage backend error). Proven not a
  regression; the next run (CI #71) went green, confirming a one-off.
- Dependency advisories (CI-FAIL-024/026): unmaintained chrono crates
  (no safe upgrade — ignored in deny.toml) and 6 lettre SMTP advisories
  (upgraded 0.11.23 → 0.11.24).
- VM resets (84 so far): every reset kills the running verify and wipes
  the native postgres/redis. Restored each time per ASSUMPTION-010
  (fresh cluster, `pf` role/db, migrations re-applied); recent resets
  are light (~30 s, binaries survive).
- Count correction: the running ticket total was one high since before
  P1-067; corrected 178 → 177 after P1-072 and owned to the user.
- Review catches: the P1-085 adoption review found a missing `unit` in
  the warning-mail payload (a real mail would have failed to render);
  the P1-080 adoption fixed three defects in an uncompiled draft
  (cargo was not on that run's PATH).
